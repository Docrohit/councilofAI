# Investigate a Council bug

Symptom/expectation: [description]. Scope: [diagnose / diagnose and fix]. Inspect
source, revision and test/log evidence. Diagnosis alone does not authorize
runtime edits. Use disposable fixtures first; preserve real accounts/projects
and bound any authorized paid calls.

Trace input, validation, state, tools/providers, checkpoint/events and UI.
Distinguish finding disputes, direct-thread proposals and candidate reviews.
For empty answers inspect saved final text, status and errors before blaming
rendering. Record reproduction, impact, source-backed cause and uncertainty.

If fixing is authorized, add a failing regression, make a scoped correction
and verify adjacent failure paths. Never weaken tests to preserve a defect.
Use docs/BUG_REPORT_TEMPLATE.md; update known issues only after verification.
Independent review precedes staging; production fixes need release approval.
